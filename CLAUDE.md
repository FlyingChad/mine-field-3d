# Mine Field 3D

Real-time multiplayer competitive minesweeper in a 3D world. Players are avatars walking a shared minefield in the browser: either a dungeon of rooms and corridors (a new one every round) or an open 32×32 field. A Python server is authoritative over all game state.

## Run

- Windows: `start.bat` (creates `.venv` and installs `aiohttp` on first run), or `.venv\Scripts\python server.py --port 8080`
- Open http://localhost:8080. `?room=x&name=y&char=wizard&realm=moon&layout=dungeon&autojoin=1` skips the join screen, which is useful for testing.
- Node is **not** installed on this machine. Python 3.11 is. There is no JS build step: the client is plain ES modules, and Three.js 0.160.0 is bundled at `static/vendor/three.module.js` (MIT, self-contained), mapped through an importmap in `static/index.html`.
- Tests: `.venv\Scripts\python -m unittest discover -s tests` (stdlib unittest; pytest is not installed). Runs in a few seconds.

## Layout

- `server.py`: aiohttp app that serves `/`, `/static/*` and the `/ws` WebSocket. Game rules live in `Room`: layout, lazy mine generation that keeps the first dig safe, flood-fill, chording, flags, scoring, health, power-ups, round end and restart. Tunables are constants at the top (`W`, `H`, `MINE_DENSITY`, `REACH`, `STUN_SECONDS`, scoring, health, items, `TICK_HZ`).
- `layouts.py` (pure Python, shared by `server.py` and `ai/env.py`): which tiles of the W×H grid (48×48) are floor.
  - `field` is a `FIELD_SIZE`² square in the middle.
  - `dungeon` is rooms joined by L-shaped corridors (a spanning tree plus a few loops); the outer ring is always wall.
  - Rules on a layout:
    - walls are never mined, revealed, flagged or reachable;
    - `Room.nb()` gives floor-only neighbours (use it for flood fill, chording and blast rims);
    - `Room.is_floor()` guards every target tile;
    - mines = `MINE_DENSITY` × floor tiles, so use `room.n_mines` / `len(room.mines)`, never `MINES`;
    - players spawn with `Room.place()`.
  - Each dungeon round generates a new layout, and the `round` message carries `spawns`.
  - In dungeons the server ignores `move`s whose centre is inside a wall; the client collides with walls (`solidAt`).
- **Health** (`MAX_HP`, `*_DAMAGE`, `KO_PENALTY`, `RESPAWN_SECONDS`, `FOOD`):
  - mines, scatter blasts and shockwaves deal damage through `Room.hurt()`, which queues knockouts; call `flush_kos()` after broadcasting the event;
  - at 0 HP a player loses points, drops their held item and is stunned until `Room.respawns()` puts them back on a random floor tile at full HP;
  - food (`apple`, `potion`) is a power-up that is only picked up when hurt.
  - Health is simulated in `ai/env.py` only with `rich=True` (v2+); food only with `extras=True` (v3). Hurt v1/v2 bots walk toward visible food (a heuristic in `update_bots`).
- **Bosses** (`server.py` `Boss`, `BOSS_*` and `ATTACK_*` constants; models in `static/bosses.js`):
  - Kinds: `ogre`, `wraith`, `golem`; ids must match `BOSS_KINDS` and `BOSSES`. Only dungeon layouts have bosses (1, or 2 with 4+ players).
  - Behaviour (`Room.update_bosses`, every tick): wander with BFS paths (`Room.bfs`, 8-way, never cutting wall corners), chase the nearest player in `aggro` range with line of sight, then a telegraphed wind-up (`bossAtk`) → `boss_smash` (damage via `hurt()`, shield absorbs).
  - Players hurt bosses with `attack` (melee, `ATTACK_*`) and power-ups (`BOSS_POWER_DAMAGE`; shockwaves and blasts stagger them, freeze freezes them).
  - `damage_boss` → `boss_down`: rewards, loot (items may sit on unrevealed tiles) and a respawn timer.
  - Bosses ride in the 15 Hz `players` message as `b` rows. Bot heuristics: swing at bosses in range, and treat bosses as targets in `bot_use`.
  - Not in `ai/env.py`.
- **The vault** (`VAULT_*`, `CHEST_POINTS`, `KEY_BIT`; dungeon layouts only):
  - `Room.setup_vault()` runs in `new_round()`. It finds a straight 2-tile cross-section of a corridor whose removal cuts off a `VAULT_MIN..VAULT_MAX` region (8-way, the way flood fill spreads; `_small_side`). Those two tiles become `room.doors`, which are **walls** (`floor = 0`) while locked; the region is `room.vault`.
  - Because doors are walls, bosses, bots (`floor`), flood fill and movement all treat them as walls with no special cases. `room.spawn_tiles` excludes the locked vault. Use it, not `floor_tiles`, for spawns.
  - `locked_out(p, i)` stops digging, flagging or blinking into the vault from outside (`can_act`, `use`).
  - `generate()` buries a `chest` plus `VAULT_LOOT` items inside, and one `key` outside. `key` and `chest` are item kinds that are not in `ITEM_WEIGHTS`.
  - Key pickup sets `p.key` (fx `KEY_BIT`). `check_doors()` runs every tick: the carrier within 1 tile of a door → `open_vault()`. That makes the doors floor, adds them to `floor_tiles` and `safe_left`, broadcasts `door`, then reveals them with `open_tiles` (flood into the vault).
  - A KO or disconnect calls `drop_key()`. A lost key (scatter) is re-buried by `check_doors()` → `bury_key()`, so the round can always finish.
  - Bot heuristic: a bot carrying the key BFS-walks to the door.
  - Not in `ai/env.py`.
- **Spike traps** (`TRAP_*`, `SPIKE_*`): `room.traps` maps tile → phase offset, placed in `generate()` on safe tiles without items.
  - They're announced when revealed (`reveal.traps`, `snapshot.traps`), and spikes are up when `(now + phase) % SPIKE_CYCLE < SPIKE_UP`.
  - `Room.spikes(now)` runs every tick: `hurt()` + stun, with a shield absorbing it and `SPIKE_GRACE` per player. Scatter removes traps in its area.
  - The client animates them from server time (`serverTime` in `welcome` → `serverNow()`).
  - v1/v2 bots won't step onto revealed traps (heuristic). Traps are simulated in `ai/env.py` for v3 (`extras`), in steps (`RICH` spike_*), so keep those in step with `SPIKE_*`.
- **Daily dungeon:** room name `daily_name()` = `daily-YYYY-MM-DD` (server's local date) → `make_room` creates `Room(daily=date)`.
  - Forced race / dungeon / `daily_realm(date)`. `self.rng` is `random.Random("mf3d-" + date)` and is re-seeded every round, so layout, vault, mines, items and traps match for everyone. Mines that fall in the first dig's 3×3 are moved with the same rng.
  - Use `self.rng` (not `random`) for anything that should match in the daily.
  - `end_round` records humans in `store.Daily` when not failed. `GET /api/daily` serves the board (best score and fastest clear per name).
- **Profiles and hats** (`store.py`): the browser sends `profile` (32-hex token kept in localStorage; never broadcast) on join.
  - `profiles.get()` creates the entry, and `Room.stat(p, **inc)` bumps it, from `open_tiles` (tiles), `explode` (mines), `boss_down` (bosses), `flush_kos` (PvP kos) and `end_round` (rounds, wins, flags, coop_wins, daily, best).
  - Unlocks are sent as `profile {stats, unlocked, hats, new?}` to that player only.
  - `store.HATS` (server, decides unlocks) and `static/hats.js` `HATS` (models) must match. `pick_hat` refuses locked hats, and the hat is in roster entries.
  - Files: `data/profiles.json` and `data/daily.json` (or `$MF3D_DATA`), saved atomically every 10 s and on shutdown; `data/` is gitignored.
- **Connection safety / resume / spectators** (`ws_handler`):
  - Every connection has a `RateLimit` token bucket (`RATE_*`); `RATE_KICK` dropped messages closes it with code 1008. `max_msg_size=MAX_MSG_BYTES` closes oversized messages with 1009.
  - Each `Player` has a `token` (sent only in its `welcome`). On disconnect the player moves to `room.away[token]` for `RESUME_SECONDS`, and `join {resume: token}` → `resume()` restores the same object (id, score, HP, items), resetting it if a new round started meanwhile (`p.round_id`).
  - A resume while the old socket is still open replaces it, and the old handler's cleanup is skipped because `player.ws is not ws`.
  - `broadcast` never removes players (the handler's cleanup does). Rooms close in `tick_loop` once `has_humans()` is false: no humans, nobody in `away`, and past `hold_until` (60 s grace for brand-new rooms, e.g. ones the lab put bots in).
  - `join {spectate: true}` adds a `Spectator` to `room.spectators`. Spectators get every broadcast, aren't on the roster, and can't act. The client runs `spectatorFrame` and follows `specTarget`.
- **Quick chat and pings:** `emote {id}` (id in `QUICK_CHAT`; the client has the text in `QUICK`) and `ping {x, y}` are broadcast as-is, limited by `CHAT_COOLDOWN` per player. There's deliberately no free-text chat.
- **Replays and the run recap** (`replays.py`, `Room.start_recording`, the hooks in `broadcast` and `end_round`; client: the "run recap" and "replays" sections of game.js):
  - A `Recorder` covers one round, or one whole descent run (`new_round()` sets `rec_pending` only when not `next_floor`). It starts on the first `broadcast` with a human in the room, opening with a spectator `welcome_msg` (no token) and a `roster`. Then every broadcast goes through `rec.add(msg, data)`: kept serialised with its time, `players` ticks only every `TICK_EVERY`. Recording stops after `MAX_SECONDS` / `MAX_BYTES` (`truncated`), but the recap keeps counting.
  - `send_to` messages (radar, profile, a player's own welcome) are never recorded, so replays hold only what a spectator sees. Keep it that way: never broadcast tokens.
  - The recap (per-player stats, a score series sampled every `SAMPLE_SECONDS`, up to `MAX_MOMENTS` moments) is tallied in `Recorder._tally` from the broadcasts. **A new event worth a stat or a moment goes there.** `end_round` sets the final scores, adds `recap` and `replay` (id, or null under `MIN_SECONDS`) to `over`, records `over`, then saves in an executor (`save_replay` → `Replays.save`: gzipped `data/replays/<id>.json.gz` plus `index.json`, newest `MAX_REPLAYS`). `close_room` drops an unfinished recording.
  - `GET /api/replays` (index) and `GET /api/replay/{id}` (12-hex id, served gzip as is).
  - Client: `?replay=<id>[&t=secs]` → `openReplay`. It feeds the events to `handle()` as a spectator (`replay` state; `replayFrame` advances the clock in `frame()` and sets `serverOffset` so traps animate). `replaySeek` restarts from the welcome when going back and fast-forwards with `quiet()` true: `tone`, `noise`, `burst`, `explosion`, `floatText`, `sayBubble`, `addPing`, `telegraph`, `showBanner`, `feed` and `refreshBoard` skip work, then leftover effects are flushed. New effect helpers should check `quiet()` too.
  - `renderRecap` (results overlay) draws the SVG score chart, stat table and moments. The join screen lists `/api/replays` (`renderReplays`).
- **Lobby:** `GET /api/rooms` (`lobby_summary()`) lists open rooms with public info only: name, mode, layout, realm, state, player names, colours and scores, progress, bosses and lives.
  - The join screen polls it every 3 s while open (`refreshLobby` / `renderLobby` in game.js). Join buttons fill the room field and submit.
  - Typing an open room's name shows `#roomNote` and dims the new-room settings, since those only apply when creating a room.
  - Rooms close `RESUME_SECONDS` after their last human leaves (see resume above). Joining a room with `MAX_PLAYERS` players gets `error {message, full}`; the client closes the socket and shows the message (rooms can still be watched).
  - Lobby entries also carry `spectators`, `away`, `daily` and `vault` (null / "locked" / "open"). The join screen also shows the daily card (`renderDaily`, polls `/api/daily` every 15 s) and a Watch button per room.
- **Game modes** (`Room.mode`, `MODES`; chosen by the room's creator like realm and layout):
  - `race` is the original game.
  - `pvp`: `Room.attack` also hits players (`PVP_MELEE_*`), and `hurt(..., by=)` credits `KO_REWARD` to whoever caused the knockout.
  - `coop`:
    - `hits_players()` is False, so no power-up or melee hits teammates;
    - no scatter bombs are generated or dropped;
    - boss HP scales with the player count;
    - `room.lives` is a shared pool (`COOP_LIVES_BASE` + 1 per player). Every KO costs one, and at 0 `flush_kos()` ends the round with `failed=True`.
  - Any new damage source must pass `by=` to `hurt()` and respect `hits_players()`.
  - `descent` (`DESCENT_*`, `FLOOR_BONUS`, `STAIRS_AUTO`, `DESCEND_DELAY`):
    - `Room.coop` is true for both coop and descent, so every co-op rule applies. Check `self.mode == "coop"` only for co-op-specific things, such as the `coop_wins` stat.
    - Descent is always a dungeon. `room.depth` is the floor; the realm is `DESCENT_REALMS[depth-1]` and the mine density grows with depth. `boss_target_count()` adds bosses every `DESCENT_FLOORS_PER_BOSS` floors, and boss HP scales with depth.
    - `open_tiles` calls `floor_cleared(p)` when `safe_left` hits 0. In other modes that just calls `end_round()`; in descent it places `room.stairs` near p, pays `FLOOR_BONUS × depth` to everyone, adds a life, clears the bosses and broadcasts `stairs`.
    - `check_stairs(now)` runs every tick: a conscious player on the stairs, or `STAIRS_AUTO`, triggers `descending`. After `DESCEND_DELAY` comes `next_floor()`: depth+1, then `new_round(next_floor=True)`, which keeps `run_id`, lives and scores. Players get full HP and lose timed effects and the key, then `round {snapshot, spawns, depth}`.
    - `run_id` changes only for a new run (or a new round in other modes). `Player.round_id` stores the `run_id` it belongs to, so a resume mid-descent keeps the score.
    - The run ends only via co-op lives (`flush_kos` → `end_round` failed). `over` carries `depth` and `runSecs`, and `store.Descents` records the team (`GET /api/descents`, the "Deepest descents" column on the join screen). The `deepest` stat (a max, via `stat(deepest=)`) unlocks the `lantern` hat.
    - Client: the `round` handler rebuilds the world when `snapshot.realm` changes, and `#fade` / `showBanner` cover the floor change.
    - Bots BFS-walk to the stairs, and v2 brains are told the mode is `"coop"`, since the AI only knows race, pvp and coop.
    - `floor_cleared` also pays correct flags (`stairs.flags`), because descent never reaches a normal `end_round`.
    - **Shop** (`SHOP`, `SHOP_OFFERS`, `SHOP_PRICE_PER_FLOOR`): `floor_cleared` picks `room.shop` (sent in `stairs.shop` and in snapshots). `buy {id}` → `Room.buy`, valid only while the stairs are open and not yet descending, once per offer per player (`p.bought`), and `life` once per floor (`room.life_bought`).
    - Shop effects:
      - `vitality` raises `p.max_hp`. **Use `p.max_hp`, never `MAX_HP`, for a player's health cap**; it's sent as the 9th field of each `players` row, and a new run resets it.
      - `shield`, `boots` and `radar` go into `p.perks` and are applied in `next_floor()`. Radar waits for the floor's mines in `perk_tick()`.
      - `supply` gives a held item now. The `bought` message is broadcast.
    - **Modifiers** (`MODIFIERS`): `room.modifier` is rolled in `new_round(next_floor=True)` from depth 2 and sent in snapshots as `{id, name, desc}`.
      - `rich`: ×2 gain in `open_tiles`.
      - `swarm`: +1 in `boss_target_count`, × `SWARM_HP` boss HP.
      - `trove`: ×2 items in `generate`.
      - `volatile`: `VOLATILE_DAMAGE` in `explode`.
      - `unstable`: `Room.crumble(now)` every `UNSTABLE_EVERY` re-covers a 3×3 of revealed tiles away from players (no mine changes, `safe_left` goes up) → `crumble {tiles, safeLeft, x, y}`.
      - `cursed`: `Room.flag` refuses flags (the client nags instead of sending).
      - `flooded`: `MODIFIERS["flooded"]["slow"]` (= `FLOOD_SLOW`) goes out with the snapshot's modifier; the client multiplies its move speed by `wadeSpeed()` and shows the `water` sheet (in `lightRealm()`); bots (`update_bots`) and bosses (at spawn) are slowed server-side.
      - `dark`: client-only. `lightRealm()` dims the lights and fog (colours are linear, so use tiny values) and turns on the `lantern` PointLight. That light is `visible = false` on other floors so it costs nothing in shaders.
    - **Elites** (`ELITE_*`): `new_round` sets `elite_due` on every `ELITE_EVERY`th descent floor; the next boss spawned is `Boss.make_elite()` (name from `ELITE_NAMES`, HP × `ELITE_HP`). Elites also wind up a quake (`b.attack = "quake"`, `bossAtk/bossSmash {quake: true, r: ELITE_QUAKE_RADIUS}`) when the target is within `ELITE_QUAKE_RANGE`; rewards × `ELITE_REWARD` and more loot. The 9th field of a `b` row is the elite flag (client `makeBoss(id, kind, elite)` wraps the model in a scaled group, plus a gold aura). Names must match `ELITE_NAMES` in game.js.
    - **Relics** (`RELICS`, `RELIC_OFFERS`): `floor_cleared` sends each human a private `relics {offer}` (bots `pick_relic` at once); client → `relic {id}` → `Room.pick_relic` (only while the stairs are open, one per floor) → broadcast `relic {pid, id, name}`. `p.relics` lasts the run (`restart_later` clears it). Effects: `iron` and `phoenix` in `hurt()` (a Phoenix save is queued in `room.saves` and broadcast as `phoenix {pid}` by `flush_kos`), `greed` in `open_tiles`, `brute`/`vampire` in `attack`, `sapper` in `explode`, `boots` in `spikes`, `scavenger`/`cartographer` in `next_floor`. Client `RELIC_NAMES` must match.
    - **Weekly descent** (`WEEKLY_PREFIX`, `this_week()`, `weekly_name()`): `make_room` creates `Room(weekly=week)` (forced descent). `self.rng` is `Random(f"mf3d-{week}-{depth}")` per floor, and the modifier and shop use it too. `generate()` for seeded rooms (daily or weekly) places mines, loot, traps and the key from the seed *before* moving the mines out of the first dig's 3×3, so loot and traps match exactly between teams. `descent_board.record(..., week=)` also keeps a per-week ladder; `/api/descents` returns `weekly`, `week` and `room`.
    - Headless Chrome (SwiftShader) is very slow with point lights (spooky, volcano, dark floors) and can time out; check those with `--dump-dom` plus a debug `document.title`, or on a real GPU.
- **Touch / mobile** (game.js `IS_TOUCH`, `body.touch` CSS; `?touch=1` forces it on desktop):
  - Controls: a pointer-events joystick (analogue; full tilt sprints) and Dig / Flag / Attack / Use / Jump buttons.
  - Dig and Flag act on `digTarget()`, shown by the pulsing yellow `digMark`: the tapped tile if it's in reach, else the hidden tile in the facing direction (`me.r`), else the hidden neighbour closest to it. Holding Dig repeats every 320 ms.
  - View gestures: tap = aim at the tile (`touchAim`, for power-ups too) and dig it if it's in reach; long-press = flag; one-finger drag turns the camera; pinch zooms.
  - With touch, `updateHover()` reads `touchAim` instead of the mouse.
  - Phones render at pixel ratio ≤ 1.5 with a 1024 shadow map, and realms get `ctx.quality = 0.5`, which halves instanced props and weather.
  - Full screen: `goFullscreen()` (Fullscreen API, needs a user gesture) runs on Join / Watch taps on touch devices, and the `#fsBtn` ⛶ button (shown on touch when not full screen; `syncFsBtn`) restores it. `static/manifest.json` (`display: fullscreen`, icons in `static/icons/`, drawn by a throwaway script) makes it installable over HTTPS; `beforeinstallprompt` shows `#installBtn` on the join screen. There's no service worker, on purpose (no stale cached code).
  - Headless Chrome won't go below about 500 px wide, so test portrait at 520×1000 and landscape at 844×390.
- `static/game.js`: the whole client:
  - the Three.js scene and instanced tile meshes (`refreshBoard()` rebuilds them from `tiles`);
  - `setLayout()`, which positions the per-tile base blocks and dungeon walls;
  - avatars with health bars, movement with wall collision, and the camera;
  - mouse picking, effects and WebAudio sounds;
  - the HUD and minimap (`drawMinimap`);
  - the character, realm and map picker;
  - networking (`handle()`).
- `static/realms.js`: the worlds a room can take place in (`meadow`, `desert`, `tundra`, `volcano`, `moon`, `candy`, `jungle`, `reef`, `spooky`, `neon`). Each realm defines:
  - a palette: sky, fog, lights, ground, cover and slab colours, plus `wall` = [side, top] for dungeons;
  - a `gravity` multiplier for jumping;
  - `decor(ctx)`, which builds scenery and weather into `ctx.group` and registers per-frame callbacks with `ctx.tick(fn(dt, t, me))`.
  - Scenery helpers: `instanced()`, `around()`, `weather()`, `clouds()` and `starfield()`.
  - `buildWorld(realmId, extent)` in game.js tears down the old realm and builds the new one.
  - Ids must match `REALM_IDS` in `server.py`. Whoever creates a room picks its realm and layout; later joiners get the room's.
  - Keep covers, slabs and walls clearly different colours, so numbers and walls stay readable from the overhead camera.
  - Thin GL lines (GridHelper) don't render reliably, so draw floor grids as textures.
- **Power-ups** (`server.py`, the `ITEM_*`, `THROW_RANGE` and `SCATTER_*` constants): `ITEMS_PER_ROUND` items are buried under random safe tiles. Digging a tile exposes its item, and walking onto it picks it up (`Room.pickups`, run every tick).
  - `scatter` is held and thrown with G. After `SCATTER_FUSE` it re-covers a (2R+1)² area, wipes the flags, craters and items in it, and scatters `SCATTER_MINES` new mines there. The total mine count can therefore change, so use `len(room.mines)`, never `MINES`, once mines exist.
  - `shield` absorbs one mine or blast.
  - `radar` privately sends the nearby mines to its holder.
  - `boots` is a speed multiplier; movement is client-side for humans and server-side for bots.
  - `gold` multiplies reveal points by `GOLD_MULT` for `GOLD_SECONDS`.
  - Held items (`HELD`: `scatter`, `freeze`, `shockwave`, `blink`) take the player's single item slot and are used with G (`use {x, y}` → `Room.use`, which checks the range for each item).
  - `freeze` fires a beam `FREEZE_RANGE` tiles long. The first other player within `FREEZE_WIDTH` of the beam is frozen: stunned, plus `frozen_until` for the ice visual.
  - `shockwave` stuns everyone within `SHOCK_RADIUS`.
  - `blink` teleports the user; the server sets a short `move_lock` so stale client `move`s can't undo it.
  - A shield absorbs a mine, a blast, a freeze or a shockwave (`Room._absorb`).
  - Adding a power-up means four changes:
    - an `ITEM_WEIGHTS` entry, plus a `HELD` entry if it is held;
    - its effect in `Room.pickups` (instant) or `Room.use` (held);
    - a bot heuristic in `Room.bot_use`;
    - on the client, `ITEM_INFO`, `itemModel()` and a message handler in game.js, plus an fx bit if other players need to see its effect.
  - Power-up effects are **not** simulated in `ai/env.py` (v3 only sees pickups as generic items worth a small reward). Bots pick them up by walking over them and use held ones through the heuristics in `Room.bot_use`.
- `static/characters.js`: 18 procedurally built characters, including dragon, mech, alien, viking, skeleton and bee. Each one is a `build(color)` that returns `{root, upper, feet, top, tick?}`. The player's colour is the character's accent.
- `static/hats.js`: unlockable hats (`buildHat(id, color)`, `HAT_HEIGHT`). A hat sits on the character's `upper` at `top`, and `makeAvatar` raises the name tag, health bar and held item by `HAT_HEIGHT`.
- `store.py`: `Profiles` and `Daily` JSON stores (see Profiles and the daily dungeon above).
- `static/index.html`, `static/style.css`: the join/picker panel (daily card, lobby, hats, stats), HUD (quick-chat bar, spectator bar, reconnect banner) and results overlay.

## AI opponents (neuroevolution) — `ai/`

- `ai/env.py` `MineEnv`: a vectorised PyTorch copy of the game rules on a tile grid. It runs N boards × A agents as tensors, on the GPU during training. There are 26 actions: 8 moves, 9 digs and 9 flags within reach. `encode()` and `action_mask()` are standalone functions shared with the in-game bots. **Any rule change in `server.py` must be mirrored here**, or bots will train on a different game from the one they play.
  - **Model versions.** v1 is classic minesweeper: 10 channels + 3 globals, 26 actions. v2 plays every mode:
    - 13 channels: v1's plus boss, danger (boss wind-up zone) and ally; out-of-bounds stays the last channel;
    - 13 globals: v1's 3, own HP, mode one-hot, and boss direction / distance / present / HP / winding-up;
    - 27 actions: the 27th is `ATTACK`.
    - `Spec.version` is stored with the model; old files load as v1. `obs_dim(r, version)` and `n_actions(version)` give the sizes.
    - `env.observe(a, r, version)` and `env.mask(a, version)` serve both, so v1 and v2 models can share a board.
  - `rich=True` (on whenever training v2) mirrors the game's newer layers in tile/step units (`RICH`):
    - health and KO/respawn;
    - a boss per board (`bosses=True`): delay, chase, wind-up, smash, cooldown;
    - attack: boss damage, or in PvP a rival;
    - modes per board (`mode` = race / pvp / coop / mixed): PvP KOs pay `pvp_ko`; co-op has no friendly fire, and `env.fitness()` gives every agent the team average.
    - Not simulated: held power-up effects, co-op shared lives, boss line of sight, boss HP scaling, the vault, shop and modifiers (v3 `extras` adds traps, pickups, food and descent stairs).
    - Change these in `RICH` alongside the server constants.
  - In the game, `server.update_bots` passes v2 brains an `extra` dict: HP, mode, allies, nearest boss with wind-up state, and attack_ok. The network's attack replaces the "swing at bosses" heuristic, which v1 bots still use.
  - **v3** (`extras=True`, on whenever training v3): v2 plus spike traps, pickups and descent.
    - 17 channels: v2's 12 planes, then trap (revealed), spikes up now, pickup, goal; out-of-bounds last. 18 globals: v2's with a 4-way mode one-hot (`MODES` = race, pvp, coop, descent), then goal dy / dx / distance / present. Still 27 actions.
    - Env rules (`RICH` trap_/spike_/item_/food_/stairs_ keys): revealed traps hurt + stun while up (`(t + phase) % spike_cycle < spike_up`, grace between hits); pickups (1 power-up, 2 food) are taken by walking on them once revealed (`item` reward; food only when hurt); a cleared descent board (mode 3, co-op rules, `self.mode >= 2` means co-op) pays `floor`, opens stairs 2–4 tiles away and removes the boss, then ends on `stairs` (reward to everyone) or `stairs_auto`.
    - `descent_practice` (lab field, LIVE) pre-digs that share of descent boards except a radius 1..`practice_radius` square around the first dig.
    - v2 sees descent as coop. `policy.upgrade(v2spec, w, v3spec)` maps v2 weights into a v3 layout (new inputs zero, descent = coop's weights); `_train` does it when a v2 `seed_model` seeds a v3 run of the same shape, and a test checks the logits match.
    - **v4** (`powers=True`, on whenever training v4): v3 plus power-ups.
    - Same 17 channels; 23 globals (v3's 18 + held one-hot for `HELD[1:]` + shield); 28 actions, the 28th is `USE`.
    - Env items when powers: codes from `ITEM_CODES` (1 generic, 2 food, 3 shield, 4–7 held items), drawn with the server's `ITEM_WEIGHTS` (no scatter in co-op). `self.held` / `self.shield` per agent; a shield soaks the next `_hurt` or mine. `USE` → `_use`: scatter (re-cover a 5×5, new mines, recount, `safe_total`), freeze (rival stun or boss freeze), shockwave (radius 3), blink (`_blink_spot`). Aiming is fixed and must match `Room.bot_aim` (nearest unstunned rival or boss in range; rivals first on a tie). `use_ok` masks USE when nothing would happen. `RICH` has the power constants: keep them in step with server.py.
    - `policy.upgrade` handles v2→v3, v3→v4 and v2→v4 (USE starts with bias `USE_BIAS`, no weights); `_train` warm-starts whenever an older seed has the same shape.
    - In the game, v4 brains get `held`, `shield` and `use_ok` (= `bot_aim(p) is not None`), and `update_bots` skips the automatic `bot_use` for them; `('use', 0, 0)` → `use(p, *bot_aim(p))`.
  - In the game, v3 brains also get `traps` [(x, y, up at now + `BOT_STEP_SECONDS`)], `items`, `goal` (the vault door front while carrying the key, else the stairs) and the real mode. The food, trap and goal heuristics are off for v3, except that goals further than `GOAL_NEAR` tiles are still BFS-walked.
  - `layout="dungeon"` samples boards from a cached bank of `layouts.dungeon()` maps (`self.floor`). In that mode `mines` is a density.
  - Reward shaping (training only, not game scoring): `step` (lab default −0.02) and `unflag` (lab default −0.5, charged when an agent removes its own flag) stop bots toggling a flag to pass turns. `stats["unflags"]` is charted in the Flags plot. Both lab fields are LIVE.
  - Walls block moves and digs, and appear in the observation's out-of-bounds channel.
  - In-game bots pass `room.floor` into `Brain.decide()` so they see walls the same way.
- `ai/policy.py` `Spec`: an MLP whose weights are a flat vector, so the whole population runs in one `baddbmm`. The input is a (2r+1)² × 10-channel window plus 3 global features (`obs_dim`).
- `ai/evolve.py`: the genetic algorithm (elites, tournament selection, optional uniform crossover, Gaussian mutation with σ decay). `SCHEMA` defines every hyperparameter, and the lab builds its form from it. To add a setting, add it to `SCHEMA` and read it from `cfg`. `train_process` runs in a spawned process. `run_match` runs head-to-head games.
- `ai/lab.py`: the `/lab` page and `/lab/ws` WebSocket. It starts and stops the trainer process over mp queues, streams generations, runs live watch games (CPU), matches, model and config management, and bot deployment through callbacks into `server.py`.
  - Each watch `frame` carries `net` (from `Lab._net`, built on `Spec.trace()`): bot 1's vision window, up to 40 hidden units per layer (chosen once by outgoing weight norm, so the picture stays stable), action probabilities, and the top signed contributions (activation × weight) between layers.
  - `netView` in lab.js animates it.
  - `lab.html#watch=demo` opens straight into watching saved models.
- `static/lab.html`, `static/lab.js`, `static/lab.css`: the lab UI, in plain JS. Charts are hand-built SVG using the dark categorical palette in a fixed order (`--s1..--s6` in lab.css).
- `ai/bots.py` `Brain`: turns a live `server.Room` into the training observation and returns an action. `server.BotPlayer` walks tile to tile and calls the same `Room.dig` and `Room.flag` as humans, so it follows the same reach, cooldown and stun rules.
- Starter models: `demo` (v1, classic) and `allmodes` (v2, trained on mixed modes in dungeons with bosses).
- Files: `models/*.pt` (dict: name, spec, flat weights, meta, loaded with `weights_only=True`), `configs/*.json` (saved lab configs), `runs/*.json` (generation history per run).
- PyTorch is the CUDA 12.8 build (the GPU is an RTX 5070 Ti, Blackwell). Install it with `pip install torch --index-url https://download.pytorch.org/whl/cu128`. Without torch the game still runs and the lab is disabled.
- In multi-agent boards, the acting order is shuffled per board every step. Acting first matters because the first dig of a board is guaranteed safe. A self-match should come out about 50/50, so use that as a fairness check.

## Conventions and invariants

- **The server is authoritative** for tiles, flags, scores, stun and reach. Clients send intents (`dig`, `flag`, `move`, `look`) and render what the server broadcasts. Never trust the client for game outcomes.
- **Reach:** players may only dig or flag their own tile and the 8 tiles around it (`REACH = 1`). The client checks by tile index. The server checks against the player's actual position plus a `REACH_SLACK` of 0.3 tiles for lag. Keep both sides consistent.
- **Coordinates:** tile `(x, y)` has its world centre at `((x - W/2 + 0.5) * TILE, (y - H/2 + 0.5) * TILE)` on the XZ plane, with `TILE = 2`. World z corresponds to tile y. Covers are 0.6 tall, revealed slabs sit at about 0.1, and the grass outside the board is at -0.5.
- **Tile values on the client:** `-3` wall / not in the layout, `-2` hidden, `-1` exploded mine, `0..8` revealed count.
- **Character ids** must match in three places: `CHARACTER_IDS` in `server.py`, `CHARACTERS` in `static/characters.js`, and the `COLORS` palette shared by `server.py` and `game.js`.
- Characters face +Z, stand on y = 0 and are built only from Three.js primitives (no external assets). New ones go in `characters.js` and in `CHARACTER_IDS`.
- Player-supplied strings (names, rooms) are rendered with `textContent` or canvas, never `innerHTML`.

## WebSocket protocol (JSON, field `t` is the type)

Roster entries for bots also carry `bot: true, model, difficulty`.
Client → server: `join {name, room, char, color, realm, layout, mode, hat, profile, resume?, spectate?}`, `move {x, z, r}` (about 15 Hz), `dig {x, y}`, `flag {x, y}`, `attack`, `use {x, y}` (held item; `throw` is an old alias), `look {name, char, color, hat}`, `emote {id}`, `ping {x, y}`.
Server → client:
- `error {message, full?}` (join refused, e.g. room full, or nothing to watch)
- `welcome {id, room, spectator, token, resumed?, serverTime, cfg:{…, realm, mode, daily, throwRange, scatterRadius, bootsSpeed, freezeRange, blinkRange, shockRadius, held, maxHp, keyBit, spikeCycle, spikeUp, quick, resumeSeconds}, spawn, snapshot}` (the snapshot includes `layout` (W*H string of 0/1), `layoutKind`, `items:[[x,y,kind]]`, `traps:[[x,y,phase]]`, `doors:[[x,y]]` (empty once open) and `daily`)
- `roster {players:[{id,name,color,char,hat}]}`
- `profile {stats, unlocked, hats, new?}` (only to its owner)
- `stairs {x, y, depth, bonus, flags, lives, auto, by, shop:[{id,name,desc,cost}]}`, `descending {by|null, depth, in}`, `bought {pid, id, cost, lives, held}`, `crumble {tiles, safeLeft, x, y}` (descent); snapshots also carry `realm`, `depth`, `stairs`, `modifier` and `shop`. Client → server `buy {id}`.
- `emote {pid, id}`, `ping {pid, x, y}`, `door {pid, tiles, reward}` (followed by a `reveal`), `drop {pid|null, x, y, kind}` (the key), `spike {pid, x, y, shielded, dmg, stun}`
- `players {p:[[id,x,z,rot,score,stunLeft,fx,hp]]}` (15 Hz tick; `fx` bits: 1 shield, 2 boots, 4 gold rush, 8 frozen, `KEY_BIT` (1024) carrying the key; `(fx >> 4) & 15` is the index of the held item in `cfg.held`)
- the `players` message also has `b:[[id,kind,x,z,rot,hp,maxHp,state]]` (state 0 wander, 1 chase, 2 wind-up, 3 frozen, 4 stunned)
- `bossSpawn {id, kind, name, x, z}`, `bossAtk {id, x, z, r, t0}` (wind-up telegraph), `bossSmash {id, x, z, r, hit, shielded, damage, stun}`, `bossHit {id, by, dmg, hp, x, z}`, `bossDown {id, name, killer, x, z, loot:[[x,y,kind]], rewards:{pid:pts}}`, `swing {pid}`
- `ko {pid, penalty, respawn, by, reward, lives}` (`by`/`reward` in PvP, `lives` in co-op), `respawn {pid, x, z, hp}`, `hitPlayer {pid, target, shielded, dmg, x, z}` (PvP melee)
- `cfg.mode` in `welcome`, and `mode`/`lives` in snapshots; `over` also carries `mode`, `failed` and `team` (the co-op total)
- `zap {pid, from:[x,z], to:[x,z], target|null, shielded, dur}`, `shock {pid, x, z, r, hit, shielded, stun}`, `blink {pid, from, to}`
- `reveal {pid, tiles:[[x,y,v]], gain, penalties, items:[[x,y,kind]], minesLeft, safeLeft}`
- `boom {pid, x, y, penalty, stun, damage, shielded, flagOwner, minesLeft}`
- `flag {x, y, pid|null, minesLeft}`
- `pickup {pid, x, y, kind, dur, heal?, hp?}`
- `radar {mines:[[x,y]], dur}` (sent only to the player who picked it up)
- `throw {id, pid, x, y, fuse, r}`
- `scatter {id, pid, x, y, r, added, tiles:[[x,y,v]], hit, shielded, stun, minesLeft, safeLeft}` (tiles set to `-2` are covered again; rim tiles carry their new counts)
- `over {results, mines, next, duration, recap, replay}` (`recap {id, duration, players:[{id,name,color,bot,score,tiles,mines,kos,pvpKos,bossDmg,bossKills,items,spikes,used}], series {t, scores:{pid:[...]}}, moments:[[t, kind, text, pid]], truncated}`; `replay` is the replay id or null)
- `round {snapshot, spawns:{pid:[x,z]}}`

## Testing

`tests/` holds the suite, run with `.venv\Scripts\python -m unittest discover -s tests`. It uses stdlib unittest.
- `helpers.py` points `MF3D_DATA` at a temp folder before importing `server`. It also provides `FakeWS`, `player()`, `at()`, `field_room()` (a whole-grid field, so fixed coordinates are valid) and `vault_room()`.
- `test_rules.py` covers the core rules. `test_features.py` covers the vault, traps, daily, profiles and the protocol, using an in-process `aiohttp.test_utils.TestServer` with `make_app(lab=False)`.
- `test_env.py` covers `ai/env.py` on the CPU, plus an in-game bot. It's skipped without torch.
- When reading from a socket in tests, remember the 15 Hz `players` tick never stops: wait for a specific message type, or collect for a fixed time window.
- Add tests there for new rules. Other techniques:
- Drive `server.Room` directly from a Python script with a fake websocket (an object with an async `send_str`) to test rules, reach and the round lifecycle.
- Use `aiohttp` client scripts as bots for end-to-end protocol checks.
- For visual checks, use headless Chrome: `chrome.exe --headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --screenshot=out.png --virtual-time-budget=6000 "http://localhost:8080/?name=T&autojoin=1"`. Add `--enable-logging=stderr` and grep for `Uncaught` to catch JS errors.
- Restart the server after editing `server.py`, `layouts.py` or anything in `ai/`. Static files are served fresh.
- Rule tests with fixed coordinates are easiest on a whole-grid field: set `server.FIELD_SIZE = 48` and use `Room(name, realm, "field")`. `python layouts.py 48 48` prints a sample dungeon.
- Headless Chrome uses a slow software renderer. With `--timeout` (real time), busy scenes may not have processed any messages yet. Prefer `--virtual-time-budget`, which waits for the page.
- For AI changes: rule-check `MineEnv` on small boards (first dig is safe, counts match a conv of the mines, flood fill is complete, mine = −10 plus stun, flags score at episode end). Then drive `/lab/ws` with an aiohttp script (`start` → wait for `status: stopped` → `match` / `addBot`). `lab.html#watch` opens straight into the live watch view.
